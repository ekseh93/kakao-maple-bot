# 보안·운영 설계

문서 버전: 1.0

## 1. 위협 모델

보호 대상:

- Kakao 봇 계정
- 백엔드 공유 비밀
- Nexon·KRX·Tiingo API 키
- 허용 채팅방과 관리자 설정
- 참여자의 대화와 표시명

주요 위협:

- 외부인이 공개 API Gateway URL을 호출
- Git·로그·오류 메시지로 비밀 유출
- 재전송으로 중복 답장
- 긴 메시지·명령 반복으로 무료 한도 소진
- 외부 API 지연으로 공기계 스레드 고갈
- 잘못된 링크·입력으로 콘텐츠 주입
- 공기계 탈취·분실·배터리 최적화로 운영 불안정
- Kakao 정책 탐지·신고에 따른 계정 제한

## 2. 신뢰 경계

1. KakaoTalk ↔ 공기계: 비공식 자동화 경계
2. 공기계 ↔ API Gateway: 공개 인터넷 경계
3. Lambda ↔ 외부 API: 제3자 공급자 경계
4. GitHub ↔ CI/AWS: 배포·비밀 경계

각 경계에서 입력을 신뢰하지 않고 별도 검증합니다.

## 3. 인증

MVP 최소안:

- Authorization: Bearer <BOT_SHARED_SECRET>
- 32바이트 이상 무작위 secret
- Lambda 환경 변수 또는 AWS secret 경로와 공기계 로컬 설정에만 저장
- 문자열 비교는 일정 시간 비교를 권장

권장 강화안:

- X-Timestamp와 X-Signature
- HMAC-SHA256(method + path + timestamp + body hash)
- 허용 시각 오차 5분
- eventId 재사용 거부

공기계 런타임에서 HMAC 구현이 불안정하면 Bearer + 높은 엔트로피 + rate limit으로 MVP를 시작하고 ADR에 기술부채를 기록합니다.

## 4. 권한

- ALLOWED_ROOMS: 기본 거부
- ADMIN_SENDERS: 상태·중지·캐시 명령만 허용
- 기능 플래그: MAPLE_ENABLED, STOCK_ENABLED 등
- 전역 KILL_SWITCH: false일 때 health 외 모든 명령 무시 또는 점검 메시지

표시명은 변경·충돌할 수 있습니다. MessengerBot R이 안정적 ID를 제공하지 못하면 방 이름과 관리자명만으로 강한 인증을 주장하지 않고, 관리자 변경 작업을 MVP에서 서버 콘솔로 제한합니다.

## 5. 속도 제한

권장 초기값:

- 방 단위: 10초에 5건, 분당 20건
- 발신자 단위: 분당 10건
- 전체: 분당 60건
- 외부 캐릭터 조회: 동일 캐릭터 5분 캐시
- 알 수 없는 명령: 방당 10초에 1회만 답변

초과 시 외부 API를 호출하지 않습니다. 반복 초과에는 답변 자체를 생략해 메시지 폭주를 막습니다.

## 6. 비밀 관리

- .dev.vars, .env, Android local-config.js는 .gitignore에 포함합니다.
- .env.example에는 값이 없는 변수명만 둡니다.
- GitHub Actions에는 실제 배포 키를 MVP에서 넣지 않습니다.
- 로그 필터가 Authorization, appkey, appsecret, access_token을 제거해야 합니다.
- 유출 의심 시 공유 비밀 → 공급자 키 순서로 즉시 회전합니다.

## 7. 공기계 하드닝

- 개인용 주계정과 분리하되 허위·대량 계정 운영은 하지 않습니다.
- 화면 잠금과 기기 암호화를 사용합니다.
- 원격 찾기·초기화를 설정합니다.
- 카카오톡과 MessengerBot R 외 앱 설치를 최소화합니다.
- 알림 접근 권한이 필요한 앱 목록을 주기적으로 확인합니다.
- 배터리 최적화 예외와 자동 재시작을 검증합니다.
- USB 디버깅은 설치가 끝나면 비활성화합니다.
- 봇이 참여한 방에는 자동화 계정임을 알립니다.

## 8. 운영 런북

### 시작

1. API Gateway/Lambda health 확인
2. 공기계 네트워크·충전·알림 권한 확인
3. 비공개 시험방에서 !상태
4. !가위바위보, !심볼, !캐릭터 순으로 검증
5. 허용 방 활성화

### 응답이 없을 때

1. 공기계 화면 잠금·네트워크 확인
2. Kakao 알림 수신 여부 확인
3. MessengerBot R 활성·컴파일 상태 확인
4. API Gateway/Lambda health 확인
5. 식별 정보 없는 requestId 기준 로그 확인
6. 외부 공급자 상태 확인

### 중복 답장

1. 공기계 봇 토글 OFF
2. 동일 스크립트 중복 활성 확인
3. eventId 생성·TTL 저장 확인
4. 재현 시험 후 제한 방에서 재개

### 계정 경고·제한

1. 즉시 봇과 자동 응답 OFF
2. 다른 계정으로 우회하지 않음
3. 최근 변경과 메시지 빈도 확인
4. Kakao 공식 안내와 이의제기 경로 확인
5. 재개 여부는 사용자가 별도 결정

### 비밀 유출

1. Lambda KILL_SWITCH
2. BOT_SHARED_SECRET 회전
3. Nexon/KRX/Tiingo 키 폐기·재발급
4. GitHub history와 로그 노출 범위 확인
5. 원인 수정·secret scan 통과 후 재개

## 9. 백업과 복구

상태를 최소화해 저장소와 secret 재등록만으로 복구 가능하게 합니다. 대화 로그 백업은 만들지 않습니다. 공기계 교체 절차는 스크립트 설치, 로컬 비밀 등록, 시험방 검증으로 제한합니다.

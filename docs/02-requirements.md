# 기능·비기능 요구사항

문서 버전: 1.0  
요구 수준: MUST, SHOULD, MAY

## 1. 기능 요구사항

| ID     | 수준   | 요구사항                                        | 수용 기준                                             |
| ------ | ------ | ----------------------------------------------- | ----------------------------------------------------- |
| FR-001 | MUST   | 느낌표 접두사 명령만 처리한다.                  | 일반 대화 100건에 답장 0건                            |
| FR-002 | MUST   | 도움말은 사용 가능한 명령과 예시를 보여준다.    | 구현된 명령과 도움말이 일치                           |
| FR-003 | MUST   | 캐릭터명으로 Nexon OCID와 핵심 정보를 조회한다. | 정상·미존재·API 오류 케이스 구분                      |
| FR-004 | MUST   | 캐릭터 상세 외부 링크를 생성한다.               | URL 인코딩 및 허용 도메인 검증                        |
| FR-005 | MUST   | 아케인/어센틱 심볼 성장치를 계산한다.           | 경계값과 공식 고정 테스트 통과                        |
| FR-006 | MUST   | 가위바위보를 지원한다.                          | !가위, !바위, !보 입력과 승패 멘트                    |
| FR-007 | MUST   | 쉼표로 구분한 2~20개 항목 중 하나를 고른다.     | 빈 항목 정리, 길이 제한                               |
| FR-008 | MUST   | 카테고리별 메뉴를 추천한다.                     | 데이터 없는 카테고리 안내                             |
| FR-009 | SHOULD | 6자리 국내 종목코드 시세를 조회한다.            | 미설정·장외시간·오류를 구분                           |
| FR-010 | MUST   | 허용된 방에서만 답장한다.                       | 미허용 방 요청은 외부 호출 없이 무시                  |
| FR-011 | MUST   | 운영자가 즉시 전체 응답을 중지할 수 있다.       | 환경 플래그 또는 공기계 토글로 차단                   |
| FR-012 | MUST   | 중복 이벤트를 짧은 시간 동안 제거한다.          | 같은 이벤트 ID 재전송 시 한 번만 응답                 |
| FR-013 | SHOULD | 공급자별 캐시를 적용한다.                       | 캐시 TTL 내 동일 조회가 외부 API를 재호출하지 않음    |
| FR-014 | SHOULD | 관리자만 상태·캐시 관리 명령을 사용할 수 있다.  | 일반 사용자의 관리자 명령 거부                        |
| FR-015 | MAY    | 방별 기능 토글을 제공한다.                      | 기본값은 최소 기능 허용                               |
| FR-016 | MUST   | 보스 결정의 파티원별 개인 수익을 계산한다.      | 정적 가격·인원 검증·버림 계산·주기별 합계 테스트 통과 |

## 2. 입력 제한

| 항목           | 제한                               |
| -------------- | ---------------------------------- |
| 전체 메시지    | 최대 300자                         |
| 캐릭터명       | 공백 제거 후 2~12자, 제어문자 금지 |
| 선택 항목      | 2~20개, 항목당 30자                |
| 종목코드       | 숫자 6자리                         |
| 방 이름·보낸이 | 권한 확인에만 사용, 영구 저장 금지 |

실제 메이플 캐릭터명 규칙이 변경될 수 있으므로 길이 검사는 보수적 사전 검사이며 최종 유효성은 Nexon API 응답으로 판단합니다.

## 3. 답변 규칙

- 첫 줄에 결과의 종류를 표시합니다.
- 핵심 결과를 8줄 이내로 우선합니다.
- 외부 데이터에는 출처와 조회 기준을 표시합니다.
- 오류 시 내부 예외·키·URL 쿼리 전체를 노출하지 않습니다.
- 링크는 HTTPS와 허용 목록 도메인만 출력합니다.
- 주식에는 “참고용이며 투자 권유가 아님”을 표시합니다.
- 환산 링크에는 “외부 사이트에서 직접 확인”이라고 표시합니다.

## 4. 비기능 요구사항

### 성능

| ID           | 요구사항                                                              |
| ------------ | --------------------------------------------------------------------- |
| NFR-PERF-001 | 로컬 계산·랜덤 명령의 백엔드 p95는 500ms 이하여야 한다.               |
| NFR-PERF-002 | 외부 API 호출은 공급자별 3초 타임아웃, 전체 요청 4.5초 예산을 가진다. |
| NFR-PERF-003 | 답변 본문은 기본 1,000자 이하로 유지한다.                             |

### 신뢰성

| ID          | 요구사항                                                                           |
| ----------- | ---------------------------------------------------------------------------------- |
| NFR-REL-001 | 한 공급자의 장애가 다른 명령에 전파되지 않아야 한다.                               |
| NFR-REL-002 | 재시도는 읽기 요청에 한해 최대 1회, 지수 백오프와 임의 지연을 사용한다.            |
| NFR-REL-003 | 중복 답장을 막기 위한 이벤트 키 TTL을 둔다.                                        |
| NFR-REL-004 | 캐시가 있으면 공급자 장애 시 데이터 시각과 함께 오래된 결과 사용을 MAY로 허용한다. |

### 보안·개인정보

| ID          | 요구사항                                                             |
| ----------- | -------------------------------------------------------------------- |
| NFR-SEC-001 | 전화 릴레이와 백엔드 사이에 공유 비밀 또는 서명 검증을 사용한다.     |
| NFR-SEC-002 | 모든 통신은 HTTPS만 허용한다.                                        |
| NFR-SEC-003 | API 키는 플랫폼 secret으로 저장하고 로그·응답·Git에 포함하지 않는다. |
| NFR-SEC-004 | 메시지 원문, 방 이름, 발신자명은 기본 로그에 저장하지 않는다.        |
| NFR-SEC-005 | 허용 방·관리자 비교는 해시 또는 설정 식별자로 수행할 수 있어야 한다. |
| NFR-SEC-006 | 의존성·비밀 스캔을 CI에서 수행한다.                                  |

### 유지보수성

| ID          | 요구사항                                                     |
| ----------- | ------------------------------------------------------------ |
| NFR-MNT-001 | 명령 라우터, 공급자 어댑터, 계산 로직, 포맷터를 분리한다.    |

| NFR-MNT-005 | 공식·정적 데이터에는 기준일과 출처를 코드와 문서에 기록한다. |

## 5. 추적성

각 구현 PR은 관련 요구사항 ID를 설명에 적고, 테스트 이름에도 가능한 한 ID를 포함합니다. 요구 변경은 문서 수정과 ADR 추가 후 구현합니다.

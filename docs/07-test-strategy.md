# 테스트 전략과 완료 조건

문서 버전: 1.0

## 1. 품질 목표

- 계산 정확성
- 비명령·미허용 방 무응답
- 외부 장애 격리
- 중복 답장 방지
- 비밀과 대화 원문 비저장
- 공기계에서 실제 한 번만 답장

## 2. 테스트 계층

### Unit

대상:

- 명령 파서
- 입력 검증
- 심볼 계산
- 가위바위보 승패와 `!메뉴Avs메뉴B` 항목 선택
- 메뉴 필터
- 출력 포맷터
- 오류 매핑

외부 네트워크 없이 실행합니다.

### Provider contract

대상:

- Nexon OCID·basic·stat·symbol fixture
- KRX 종목·일별매매 및 Tiingo 검색·가격 fixture
- 필드 누락, 타입 변경, 오류 코드

실제 사용자 응답을 그대로 커밋하지 않고 최소 익명 fixture를 작성합니다. 런타임 스키마가 예상 밖 응답을 거부해야 합니다.

### Lambda integration

대상:

- GET /health
- POST 인증 성공·실패
- 허용/미허용 방
- 명령 라우팅
- timeout, retry, cache
- 최대 본문 크기와 malformed JSON

외부 fetch는 mock 또는 local test server로 대체합니다.

### Phone relay

대상:

- 접두사 필터
- HTTP 요청 인코딩
- null reply 무시
- HTTP/JSON 오류
- 한 이벤트 한 답장
- 네트워크 복구

MessengerBot R 호환 JavaScript 문법을 실제 앱 컴파일로 확인합니다.

### End-to-end

비공개 시험방에서 실제 공기계 → API Gateway → Lambda → 외부 API → Kakao 답장을 검증합니다. 이 단계는 계정·키·배포 준비와 사용자 승인이 필요합니다.

## 4. 계산식 검증

심볼 데이터는 다음 3개 근거가 준비되어야 완료입니다.

1. 공식 출처 URL과 시행일
2. 레벨별 전체 fixture
3. 최소·중간·최대 레벨 수동 계산표

문서 예시 하나만으로 공식을 추정해 구현하지 않습니다. 패치로 수치가 바뀌면 데이터 버전을 올리고 이전 fixture 변경 사유를 ADR 또는 CHANGELOG에 기록합니다.

## 5. 정적·보안 검사

필수 CI:

- format check
- ESLint
- TypeScript strict typecheck
- unit/contract/integration tests
- dependency audit
- secret scan
- build dry run

CI는 배포하지 않습니다. 배포 워크플로는 사용자 승인 후 별도 추가합니다.

## 6. 커버리지

- core 계산·파서: branch 90% 이상
- 전체: line 80% 이상
- 커버리지 수치보다 T-001~T-020 통과를 우선

## 7. Definition of Done

기능 단위:

- [ ] 관련 요구사항 ID가 연결됨
- [ ] 정상·경계·오류 테스트가 있음
- [ ] 사용자 오류에 내부 정보가 없음
- [ ] 문서와 도움말이 갱신됨
- [ ] 데이터 출처·기준일이 있음
- [ ] 외부 서비스 정책을 위반하지 않음

MVP:

- [ ] 모든 MUST 요구사항 구현
- [ ] T-001~T-020 중 구성 가능한 항목 통과
- [ ] 실제 공기계 E2E 체크리스트 통과
- [ ] 비밀 스캔 0건
- [ ] 무료 한도와 rate limit 확인
- [ ] 운영자 승인 후에만 배포 활성화
